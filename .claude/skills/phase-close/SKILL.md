# /phase-close — Phase 종료 절차

Task.md §문서 사용 규칙(완료 기준, DoD)을 기계적으로 집행한다.
인자: Phase 번호(예: `/phase-close 8`). 없으면 Task.md 헤더의 "현재 위치"에서 대상 Phase를 추론한다.

## 1. DoD 게이트 — 하나라도 걸리면 닫지 않고 보고 후 중단

1. **미완 항목**: 대상 Phase에 `[ ]` 항목이 남아 있으면 **닫을 수 없다.** 목록을 보여주고, 이월이 타당한 항목은 어느 Phase로 옮길지 사용자에게 묻는다(선례: Phase 6→14, Phase 7→11 이월).
2. **QA 존재**: `[x]` 항목 중 `[QA]` 태그가 최소 1개 있어야 한다(DoD 규칙 4).
3. **실측 근거**: 각 `[x]`는 "MCP 실측 또는 실플레이로 확인됨"이어야 한다(DoD 규칙 2). 항목 본문·검증 기록 표·DevelopLog 어디에도 근거가 없는 항목은 의심 목록으로 보고한다 — 2026-08-07 개편의 원인이 바로 근거 없는 `[x]`였다.
4. **완료 조건**: Phase 헤더의 "완료 조건"이 실제로 관측되었는지 확인한다.
5. **태그 규칙**: 태그 없는 항목이 없어야 한다(DoD 규칙 1).

## 2. 문서 갱신 (게이트 통과 시)

- **`Task.md`**: Phase 헤더에 `✅ (YYYY-MM-DD 완료)` 표기, 문서 상단 "현재 위치"를 다음 Phase로 갱신.
- **`DevelopLog.md`**: **최상단**에 추가 — 포맷: 날짜(YYYY-MM-DD) · 제목 · 작업 내용 · 해결된 이슈 (CLAUDE.md §2.6).
- **정합성 점검**: `GDD.md` 헤더 "현재 진척"이 어긋나면 갱신하고, `TDD.md`에 이 Phase 관련 스테일 서술("미구현"·"예정" 표기 등)이 남았으면 정정한다. 정정 사실은 Task.md의 `[Doc]` 항목으로 남긴다(선례: §문서 정합성 미결 섹션).

## 3. 마무리

- 변경 파일 목록과 커밋 메시지를 제안하고 **사용자 승인 후** 커밋한다(예: `docs: close Phase N (<제목>)`).
- 다음 Phase 헤더의 **선행 조건**이 충족됐는지 확인해 한 줄로 알린다.
